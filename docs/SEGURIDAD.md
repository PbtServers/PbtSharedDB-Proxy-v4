# Seguridad

Por defecto no arranca ningún servidor SQL y el bind es local. Antes de habilitar escucha remota configure una red privada y firewall efectivo en el nodo. Una asignación de Pterodactyl puede publicar el puerto en Internet: no la cree sobre una interfaz pública sin reglas que bloqueen todos los orígenes salvo los backends autorizados. Compruebe desde una red externa que el puerto está cerrado. `0.0.0.0` únicamente controla escucha; no filtra clientes.

El plugin no tiene acceso privilegiado al host y no puede certificar el firewall/NAT. `network-isolation-confirmed` registra una decisión del administrador, no una detección. Pruebe la conectividad después de reiniciar los contenedores; NAT puede cambiar la IP que MariaDB observa. Cada combinación usuario@IPv4 necesita una entrada explícita. No se admiten hosts comodín.

MariaDB se ejecuta con el mismo UID sin privilegios que Velocity. Root y la cuenta administrativa del UID se fuerzan a autenticación unix_socket y localhost antes de abrir TCP. No hay contraseña root compartida ni root TCP. Las cuentas de aplicación reciben SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX y DROP únicamente sobre su base, sin GRANT OPTION ni privilegios globales. Estos permisos permiten al dueño destruir su base: no reutilice credenciales entre aplicaciones ajenas. No se conceden FILE, SUPER, PROCESS o administración de usuarios.

El proceso se inicia primero sin red, valida cuentas y aprovisiona mediante socket, se apaga y vuelve a iniciar con TCP. Solo se anuncia READY después de un SELECT 1 autenticado por TCP con una cuenta sin acceso a datos. El proceso nativo vivo no equivale a SQL listo. Las cuentas inesperadas causan rechazo; no se borran automáticamente.

Los secretos se generan con SecureRandom (256 bits), se preservan entre recargas y nunca se incluyen en comandos, status, info, argumentos nativos ni logs Java. Las instrucciones SQL de aprovisionamiento van por stdin del cliente. Los identificadores se validan y escapan; los valores DDL se restringen a alfabetos cerrados sin caracteres SQL, pues no todas esas instrucciones admiten parámetros. Las consultas JDBC usan PreparedStatement. No existe una interfaz para SQL arbitrario desde Minecraft.

Directorios privados 0700 y archivos secretos 0600 en Linux. Los archivos temporales SQL son privados y se eliminan. Los errores nativos SQL no se publican porque pueden contener sentencias. Un administrador del contenedor puede leer los secretos por SFTP local; cópielos individualmente al config privado del cliente y protéjalo también. No publique config de LuckPerms con contraseñas ni copias lógicas de datos de jugadores.

Consola o permiso explícito `pbtsharedb.admin` administran todos los comandos; este permiso permite detener la base y cortar los backends. No lo conceda a jugadores normales. La sugerencia de comandos respeta el mismo permiso. Los archivos YAML y las rutas del runtime son configuración administrativa confiable. Cualquier otro plugin o proceso del mismo UID puede leer datos/secretos: este diseño no ofrece aislamiento entre plugins del mismo contenedor.

La instalación automática acepta un único artefacto HTTPS con hash fijado, rechaza redirecciones y comprueba el SHA-256 antes de extraer. Limita descarga/tamaño extraído/número de entradas; rechaza escapes y tipos especiales, y omite enlaces. Nunca se descarga una URL proporcionada por un jugador. En preinstalled solo acepta nombres y directorios nativos autorizados y rechaza binarios escribibles por grupo/otros. La imagen y su proveedor siguen siendo parte de la confianza.

La conexión remota de esta versión no configura TLS. Úsela exclusivamente en una red privada confiable del nodo, aislada también de contenedores no autorizados. Para cruzar nodos o redes no confiables use un túnel cifrado administrado externamente o implemente una configuración TLS revisada antes del despliegue. No se presenta este modo como apropiado para Internet.
